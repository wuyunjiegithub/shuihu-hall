> 对应需求：01-需求文档.md　|　实现：`/workspace/shuihu-hall/`

## 1. 设计目标与原则

| 目标 | 说明 |
|---|---|
| **空间叙事优先** | 布局由原著世界观驱动（天罡在天、地煞在地），而非 UI 网格 |
| **零学习成本** | 打开即自动导览，用户不需要知道任何操作 |
| **原貌还原** | 用原版扫描卡图，保留“左图右文”的经典版式 |
| **克制的光效** | 炫但不喧宾夺主，辉光服务于“收藏品的珍贵感” |
| **离线自持** | 不依赖 CDN、不依赖后端，单目录即可运行 |

## 2. 空间设计

### 2.1 坐标系与尺度

| 元素 | 参数 | 取值理由 |
|---|---|---|
| 卡面尺寸 | 3.4 × 2.52（厚 0.06） | 严格按大卡比例 7.8 : 5.2 = 1.5 : 1 |
| 天罡环 | 半径 R=26，高度 Y=13 | 高空近中央，视觉上“星宿在上” |
| 地煞环 | 半径 R=52，高度 Y=4.5 | 地面外环，与天罡形成上下双层透视 |
| 聚义碑 | 高 15，8 棱柱，顶部光球 | 空间锚点，各角度都能看到的中心参照 |
| 地面星盘 | 半径 64 / 30 双层极坐标网格 | 星宿刻度意象，强化“星穹”主题 |
| 星空 | 6500 点，半径 150–280 | 提供深空纵深 |
| 雾 | FogExp2，密度 0.0052 | 远处卡片自然淡出，避免边缘突兀 |

### 2.2 卡片朝向

每张卡用 `group.lookAt(环外点)` 使其 **+Z 面朝环外**，即观众从外侧走近时看到卡正面。卡面 `BoxGeometry` 六材质数组中，pz 面贴原图、nz 面贴生成的卡背，因此任意角度都不会看到“空面”。

### 2.3 为什么是双环

- **叙事**：原著 108 将本就分天罡地煞，高度差天然表达“天/地”。
- **构图**：双层环产生前后景深，拍照式构图比单层更有层次。
- **动线**：巡航路径可“穿内环、绕外环”，路线自带节奏变化。

## 3. 视觉设计

### 3.1 配色

| 用途 | 色值 | 说明 |
|---|---|---|
| 主背景 | `#05040f` | 近黑的深蓝，星空对比度基础 |
| 暗金 | `#d8b56a` | 标题、边框、碑文 |
| 纸白 | `#f0e8d8` | 主标题与正文 |
| 天罡金 | `#ffe4ac` / 光晕 `255,205,115` | 天罡名牌与辉光 |
| 地煞蓝银 | `#d7e2ff` / 光晕 `135,170,255` | 地煞名牌与辉光 |
| 辅助灰紫 | `#7d7595` | 次要说明文字 |

### 3.2 字体

标题使用宋体系（`Songti SC / STSong / SimSun / Noto Serif SC`），与古典题材匹配；HUD 与正文使用同族小字号，保持统一。

### 3.3 光效

| 效果 | 参数 |
|---|---|
| UnrealBloom | strength 0.68 ± 0.08 呼吸，radius 0.55，threshold 0.78 |
| Gamma 校正 | Bloom 链路末端必须加 `GammaCorrectionShader`，否则整体偏暗 |
| 镭射流光 shader | 每张卡叠加一层加法混合的彩虹膜，天罡强度 1.0、地煞 0.55 |
| 卡背 | Canvas 程序生成：深蓝渐变底 + 金线双框 + “水滸”圆章 |

> 镭射 shader 思路：用 Fresnel（`1 - |dot(N, V)|`）作为强度基，叠加随视角流动的彩色条纹（`sin(uv.y*24 + t*0.9 + ...)`），生成随观察角度变化的彩虹反光，模拟硬闪卡质感。

## 4. 交互设计

### 4.1 状态机

```
        ┌────────────────── 点击空白 / ESC / 关闭按钮 ─────────────┐
        ▼                                                          │
   [ CRUISE 巡航 ] ── 点击命中卡牌 ──▶ [ FOCUS 鉴赏 ] ─────────────┘
```

### 4.2 相机运动

| 阶段 | 位置 | 视线 | 缓动 |
|---|---|---|---|
| 巡航 | CatmullRom 闭合曲线（15 个控制点）上的 `getPointAt(u)` | 前方 1.2% 处 × 0.72 + 中央碑 `(0,8.5,0)` × 0.28 | `k = 1 - e^(-dt·2.2)` |
| 巡航视差 | — | 叠加鼠标偏移 ±5（横） / ±2.5（纵） | 同上 |
| 鉴赏 | 卡位 + 卡法线 × 9.5，抬高 0.6 | 卡面中心 | `k = 1 - e^(-dt·2.6)` |

- 巡航周期 **130 秒/圈**，路径：高空俯冲 → 地煞外环绕行 → 升空 → 内穿天罡环 → 中央 → 拉远。
- 所有插值采用**帧率无关**的指数缓动，避免高刷新率下速度失真。

### 4.3 点击与命中容错

- Raycaster 用 `pointer.set(x/innerWidth*2-1, -(y/innerHeight)*2+1)` 换算 NDC。
- **命中热区**：每张卡额外挂一个比卡面大 35% 的隐形平面（`visible:false`，仍参与 raycast）。原因：卡在屏幕上仅约 70px 宽，直接点卡面容错太低。
- 拖动与点击区分：按下位移 > 6px 判定为拖动，不触发鉴赏。

### 4.4 鉴赏面板

右侧滑入（宽 min(88vw, 392px)），自上而下：高清原图 → 星号徽章（天罡金 / 地煞银）→ “梁山第 0xx 位 · 三十六天罡” → 绰号大字 → 姓名 → 人物小传 → 出处标注。

## 5. 技术方案

| 项 | 选型 | 说明 |
|---|---|---|
| 渲染 | Three.js r128（本地化，非 CDN） | 全局 `THREE`，无需打包工具 |
| 后期 | EffectComposer + RenderPass + UnrealBloomPass + GammaCorrection | 全部本地化 |
| 材质 | 卡面 `MeshBasicMaterial`（原图自带明暗，不受光更保真） | 避免灯光破坏原画色彩 |

| 图片格式 | WebP（640 展馆版 + 950 鉴赏版） | 体积与清晰度平衡 |

## 7. 关键决策与踩坑记录

| # | 问题 | 决策 |
|---|---|---|
| 1 | 点击飞近时镜头跑到卡背面 | `getWorldDirection()` 已返回朝外法线，多余的 `negate()` 导致反向，已移除 |
| 2 | 加了 Bloom 后整体画面偏暗 | EffectComposer 链路绕过 `outputEncoding`，必须末端补 `GammaCorrectionShader` |
| 3 | 无头环境 WebGL 无法创建上下文 | 新版 Chrome headless 禁用软 WebGL；改用 **Xvfb + headed 模式** 才拿到 SwiftShader 渲染上下文 |
| 4 | 测试时点击总是命中失败 | 自身失误：把垂直 FOV 当水平 FOV 计算卡宽，导致测试坐标落在卡外；真实结论是**卡在屏上仅约 70px** → 因此新增 35% 隐形热区 |
| 5 | 近处名牌 Sprite 过大遮挡视线 | 名牌 scale 由 4.6 缩至 2.6 |
| 6 | 巡航路径贴卡太近“卡脸” | 路径控制点外移：地煞段 R≈60–62，天罡段 R≈32–36 |
| 7 | GitHub 直连频繁超时 | 改用 gh-proxy 镜像下载资源仓库 |
| 8 | 108 张纹理内存偏大 | 展馆用 640px 缩略图，鉴赏时再加载 950px 原图 |

## 11. V1.1 架构决策

### 11.1 选型结论

**采用「原生 ES Module 多文件 + 零构建」，并附加一个单文件打包脚本。**

| 维度 | 说明 |
|---|---|
| 模块方案 | 原生 `<script type="module">`，浏览器原生加载，无需 npm / 打包器 |
| 运行方式 | 本地静态服务（提供 `start.sh` / `start.bat` 一键启动） |
| 离线形态 | Node 零依赖构建脚本产出单文件 HTML（卡图 base64 内嵌） |
| 为什么不用框架 | 场景是命令式 WebGL 渲染，React/Vue 的声明式优势无从发挥，反而增加构建负担 |
| 为什么不用单文件 | V1.1 代码量 2000+ 行，单文件无法维护 |

## 12. 布局系统设计（三种可切换）

三种布局共用同一套卡牌工厂与相机控制器，差异仅在**位置解算函数**与**巡航路径**。

### 12.1 ① 天罡地煞双星环（默认）

- 天罡 R=26 / Y=13；地煞 R=52 / Y=4.5；卡面朝环外
- 巡航路径为闭合 CatmullRom 曲线，130 秒/圈
- 语义：天罡在天、地煞在地

### 12.2 ② 悬浮岛屿

- 将 108 张卡分为 **6 座浮岛**（天罡 2 座、地煞 4 座，每岛 18 张）
- 岛屿分布在半径 30–58 的环带上，高度错落（Y=2 ~ 10），岛面为发光圆盘 + 底部锥形岩体
- 卡在岛上呈弧面/半圆排列，朝岛外
- 巡航路径在岛间穿行，视点忽高忽低
- 语义：水泊梁山“八百里水面”的聚义意象

### 12.3 ③ 悬浮长廊（螺旋）

- 108 张卡沿**螺旋上升的走廊**单列排布，螺距 ~2.2，总高 ~40
- 每张卡朝走廊中轴，观众沿螺旋由底向上（或自上而下）巡游
- 语义：工艺品位递进的展览动线，最接近真实博物馆长廊

### 12.4 切换机制

| 项 | 设计 |
|---|---|
| 触发 | HUD 顶部布局切换按钮（三组），键盘 1/2/3 亦可 |
| 过渡 | 卡牌目标位置/朝向由当前状态向新布局目标做 1.2s 缓动插值（逐个错峰 20ms 形成波浪感） |
| 相机 | 同时切换巡航曲线，相机位置向新曲线最近点平滑迁移 |
| 状态保持 | 切换不影响当前鉴赏中的卡片；鉴赏中切换则退出鉴赏 |

## 13. 工艺材质系统（四类可切换）

共用一套参数化 shader，通过 uniform 控制差异：

```glsl
// 核心：Fresnel 强度 + 彩虹相位 + 条纹密度 + 金属锐度
float fres = pow(1.0 - abs(dot(N, V)), uFresnelPow);
vec3 rainbow = 0.5 + 0.5 * cos(6.2832 * (fres * uPhaseScale + band * uBandMix) + vec3(0.0, 2.1, 4.2));
```

| 工艺 | 卡图目录 | uStrength | uFresnelPow | uBandMix | 辅助效果 |
|---|---|---|---|---|---|
| 普卡 | standard | 0.35 | 3.0 | 0.12 | 哑光纸感：低对比柔和扫描光带，随视角缓慢移动 |
| 奖闪（镭射） | flash_prize | 1.0 | 2.0 | 0.35 | 强彩虹条纹 + 高频闪烁颗粒，角度敏感 |
| 冷烫 | code_perm | 0.75 | 4.5 | 0.08 | 冷色金属高光（偏银蓝），边缘锐利 |
| 立绘 | character_art | 0.25 | 2.5 | 0.05 | 极柔光晕，突出原画本身 |

- 切换工艺时：重新绑定卡图纹理（并发加载 108 张）＋ 过渡 shader 强度动画（0.5s 交叉淡入）
- 纹理按当前尺寸策略加载（桌面 640px / 移动 480px）

## 16. 单文件离线版构建

- 脚本：`tools/build-single.js`（Node，零依赖）
- 做法：读取 `index.html` → 内联所有 `src/*.js`（按依赖顺序拼接、剥离 import/export）→ 卡图转 base64 内联 → 输出 `dist/水浒星穹卡馆.html`
- 体积预估：640px 卡图 108 张 ≈ 4.9MB → base64 后约 6.5MB，加脚本约 8MB
- 用途：双击即开、离线拷贝、发给朋友（附带版权声明弹窗）

11.2 设想的 `src/` 子目录细分（`core/` `cards/` `layouts/` `features/` `ui/`）在实现时**合并为 7 个平铺模块**：

### 17.2 新增工具

| 工具 | 作用 |
|---|---|
| `tools/serve.js` | 本地静态服务器，发送 `no-store` 强制不缓存 |
| `tools/build-single.js` | 单文件打包：资源内嵌 + 模块拼接 + 顶层重复声明检测 |

> `serve.js` 的由来：调试期间多次出现「改了代码却看不到变化」，最终定位为浏览器对 `.js` 的启发式缓存（Python 内置 http.server 不发送 Cache-Control）。这是**必须写进工具链的坑**。

### 17.4 实现中修复的缺陷

| 缺陷 | 根因 |
|---|---|
| 密室卡片完全消失 | 卡片位置重复叠加密室组的 Y 偏移（组已 −26，卡再减一次） |
| 布局切换在低帧率下停滞 | 错峰延迟用「逐帧累加 dt」，改为绝对时间戳 `performance.now()` |
| 长廊布局中聚义碑挡住螺旋中轴 | 长廊布局隐藏聚义碑，视线混合中心抬高至 y=20 |
| 岛屿岩体过亮抢视线 | 顶面与岩体颜色调暗一档 |
| 密室卡片只见侧面 | 由「朝外环列」改为「扇形展墙，全部面向入口」 |
| 移动端控件遮住大半个屏幕 | 窄屏折叠为「展厅 / 工艺 ▾」菜单 |
| 调试误判：点击命中率极低 | 实测为测试坐标换算失误；但仍据此新增 35% 隐形热区提升真实容错 |
